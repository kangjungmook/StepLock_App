# Play 스토어 출시 체크리스트

코드에서 확인한 사실을 기준으로 정리했습니다. 콘솔 화면 구성은 Google이 자주
바꾸므로 항목 이름은 조금 다를 수 있습니다.

## 1. 코드 쪽 — 끝난 것

| 항목 | 상태 |
| --- | --- |
| 계정 삭제 (앱 안 경로) | 설정 → 계정 삭제 → 확인 대화상자 |
| 계정 삭제 (서버) | `delete_own_account()` security definer 함수, `auth.users` cascade |
| 계정 삭제 (웹 URL) | [`docs/account-deletion.md`](account-deletion.md) |
| 개인정보처리방침 | [`docs/privacy-policy.md`](privacy-policy.md) |
| 릴리스 서명 설정 | `keystore.properties` 또는 환경변수로 주입, 저장소에는 없음 |
| R8 축소·난독화 | `isMinifyEnabled = true`, `isShrinkResources = true` |
| AAB 생성 | CI의 `bundleRelease` |
| 포그라운드 서비스 타입 선언 | `specialUse` + `PROPERTY_SPECIAL_USE_FGS_SUBTYPE` |

## 2. 코드 쪽 — 직접 하셔야 하는 것

### 2-1. 두 문서의 연락처 채우기

`docs/privacy-policy.md`와 `docs/account-deletion.md` 맨 위에
`여기에 연락받을 이메일을 적어 주세요`가 있습니다. **비워두면 심사에서 걸립니다.**

### 2-2. 문서를 웹에 띄우기

Google은 **공개된 URL**을 요구합니다. 저장소 설정에서 한 번만 켜면 됩니다.

`Settings → Pages → Source: Deploy from a branch → Branch: main / docs → Save`

그러면 주소가 이렇게 됩니다.

```
https://kangjungmook.github.io/StepLock_App/privacy-policy
https://kangjungmook.github.io/StepLock_App/account-deletion
```

### 2-3. 업로드 키 만들기

**이 키를 잃으면 앱을 영구히 업데이트할 수 없습니다.** 반드시 백업하세요.

```bash
keytool -genkeypair -v \
  -keystore release.jks \
  -keyalg RSA -keysize 2048 -validity 10000 \
  -alias steplock
```

만든 뒤 저장소 루트에 `keystore.properties`를 만듭니다 (`.gitignore`에 이미 들어 있습니다).

```properties
storeFile=/절대/경로/release.jks
storePassword=...
keyAlias=steplock
keyPassword=...
```

CI에서도 서명하려면 저장소 Secrets에 넣으세요.

| Secret | 값 |
| --- | --- |
| `STEPLOCK_KEYSTORE_BASE64` | `base64 -w0 release.jks` 출력 |
| `STEPLOCK_STORE_PASSWORD` | 키스토어 비밀번호 |
| `STEPLOCK_KEY_ALIAS` | `steplock` |
| `STEPLOCK_KEY_PASSWORD` | 키 비밀번호 |

Play App Signing을 쓰면 Google이 배포 키를 보관하고, 위 키는 **업로드 키**로만 쓰입니다.
분실 시 재발급이 가능해지므로 켜는 것을 권합니다.

### 2-4. Supabase 마이그레이션 적용

계정 삭제 함수가 서버에 있어야 동작합니다. Supabase 대시보드 → SQL Editor에
[`supabase/migrations/20260921120000_delete_own_account.sql`](../supabase/migrations/20260921120000_delete_own_account.sql)
내용을 붙여 실행하세요.

## 3. 데이터 보안 양식 답변 (초안)

코드를 전수 확인한 결과입니다. 광고 SDK, 분석 도구, 크래시 리포터는 **없습니다**.

**먼저 답할 것**

| 질문 | 답 |
| --- | --- |
| 데이터를 수집하거나 공유합니까? | **예** (로그인한 경우) |
| 전송 중 암호화됩니까? | **예** (HTTPS) |
| 사용자가 데이터 삭제를 요청할 수 있습니까? | **예** (앱 안 경로 + 웹 URL) |
| 데이터가 제3자와 공유됩니까? | **아니요** (Supabase는 처리 위탁이지 공유가 아닙니다) |

**수집 항목**

| 데이터 유형 | 수집 | 선택/필수 | 목적 |
| --- | --- | --- | --- |
| 이메일 주소 | 예 | 선택 (게스트 가능) | 계정 관리 |
| 사용자 ID | 예 | 선택 | 계정 관리 |
| 이름 | 예 | 선택 | 앱 기능 (인사말) |
| 건강 및 피트니스 — 건강 정보 | 예 | 선택 | 앱 기능 (걸음·수면 조건 판정) |
| 앱 활동 — 기타 사용자 생성 콘텐츠 | 예 | 선택 | 앱 기능 (잠금 설정, 잠글 앱 목록) |

모두 **선택**입니다 — 게스트 모드에서는 아무 데이터도 전송되지 않습니다.

**수집하지 않는다고 답할 것**

- 위치, 연락처, 사진/동영상, 파일, 메시지, 통화 기록, 캘린더
- 기기 ID 또는 광고 ID (기기 식별자는 앱이 만든 임의 UUID라 해당하지 않습니다)
- 앱 성능(크래시 로그, 진단) — 수집 도구가 없습니다
- **화면에 떠 있는 앱 이름** — 판단 직후 버리고 저장·전송하지 않으므로 수집이 아닙니다

## 4. 승인 절차가 따로 필요한 것

여기가 일정이 걸리는 부분입니다.

### 4-1. `FOREGROUND_SERVICE_SPECIAL_USE`

Console에 용도를 적어 제출하면 Google이 읽고 판단합니다. 이렇게 쓰시면 됩니다.

> 사용자가 직접 지정한 앱이 화면에 나타나는지 확인해, 하루 목표(걸음 수·수면 시간·
> 집중 세션)를 채우지 못한 상태면 잠금 화면을 띄웁니다. 화면이 꺼져 있거나 다른 앱을
> 쓰는 동안에도 감시가 유지되어야 하므로 포그라운드 서비스가 필요합니다.
> `dataSync`·`health` 등 기존 타입에 해당하지 않아 `specialUse`로 선언했습니다.
> 화면의 내용은 읽지 않고, 전경 앱의 패키지 이름만 확인한 뒤 즉시 버립니다.

### 4-2. Health Connect

수면 읽기는 **별도 선언 양식 + 승인**이 필요합니다. 승인이 안 나면
`sleepEnabled` 조건을 빼고 출시할 수 있게 코드가 이미 분기되어 있습니다.

### 4-3. 민감 권한 사용 설명

사용 정보 접근(`PACKAGE_USAGE_STATS`)과 다른 앱 위에 표시(`SYSTEM_ALERT_WINDOW`)는
다른 앱의 동작을 막는 데 쓰이므로 심사자가 자세히 봅니다. 디지털 웰빙 용도는 허용
범주이지만 **통과가 보장되지는 않습니다.**

### 4-4. 비공개 테스트 의무

최근에 만든 개인 개발자 계정이면 프로덕션 신청 전에 **테스터 12명 이상 × 14일 연속**
비공개 테스트가 필요합니다. 인원과 기간은 Google이 바꾼 적이 있으니 Console에서
확인하세요. **일정상 가장 오래 걸리는 항목입니다.**

## 5. 스토어 등록정보 준비물

| 항목 | 규격 | 상태 |
| --- | --- | --- |
| 앱 아이콘 | 512×512 PNG | 만들어야 함 |
| 그래픽 이미지 | 1024×500 PNG/JPG | 만들어야 함 |
| 폰 스크린샷 | 2장 이상, 16:9~9:16 | **실제 기기 캡처가 필요** |
| 짧은 설명 | 80자 이내 | 초안 아래 |
| 자세한 설명 | 4000자 이내 | 초안 아래 |
| 개발자 등록비 | $25 (1회) | |

`docs/screens/`의 이미지는 HTML로 렌더한 것이라 **스토어에 쓸 수 없습니다.**
실제 기기에서 캡처하세요.

### 짧은 설명 초안 (69자)

> 걸음 수, 수면, 집중 시간 중 하나를 채우면 쇼츠와 릴스의 잠금이 풀립니다.

### 자세한 설명 초안

> 스텝락은 쇼츠·릴스·틱톡을 그냥 막지 않습니다. 하루 습관 하나를 채우면 열어 줍니다.
>
> **세 가지 조건 중 하나만 채우면 됩니다**
> · 걸음 수 — 목표만큼 걸으면 하루 동안 열립니다
> · 수면 시간 — 충분히 잤으면 자동으로 풀립니다
> · 집중 타이머 — 25분 집중 세션을 목표만큼 끝내면 열립니다
>
> 세 조건을 모두 채워야 열리도록 바꿀 수도 있습니다.
>
> **잠긴 앱을 열면** 무엇을 얼마나 더 하면 되는지 한 화면으로 보여 줍니다.
> 급할 때는 5분만 임시로 열 수 있습니다.
>
> **기록을 봅니다** 최근 7일 걸음 수와 조건별 달성 일수를 확인할 수 있습니다.
>
> **로그인은 선택입니다** 로그인하지 않아도 모든 기능을 쓸 수 있고, 이때는 어떤
> 정보도 기기를 떠나지 않습니다. 로그인하면 기기를 바꿔도 설정과 기록을 되찾습니다.
>
> **개인정보** 화면에 떠 있는 앱의 이름만 확인하고 즉시 버립니다. 화면 내용은 읽지
> 않습니다. 광고와 분석 도구가 없습니다.

## 6. 권장 순서

1. 기기에서 실제 동작 확인 (특히 잠금 → 해제)
2. 연락처 채우고 GitHub Pages 켜기
3. 업로드 키 만들고 백업
4. 개발자 계정 등록 ($25)
5. 스토어 등록정보와 스크린샷 준비
6. 데이터 보안 양식 + `specialUse` 설명 + Health Connect 선언 제출
7. 비공개 테스트 (12명 × 14일)
8. 프로덕션 신청
